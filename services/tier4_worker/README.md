# Tier 4: PPO Training & Rollout Worker

This worker is responsible for polling the `tier3.replay_buffer` for completed RLHF `ExperienceTuples` and triggering the PPO (Proximal Policy Optimization) Actor-Critic step to finetune the frozen SAM2 models via LoRA.

## RL Framework Choice: PyTorch Native vs Stable Baselines3 (SB3)

For this implementation, we have stubbed the architecture using **Native PyTorch** rather than Stable Baselines3.

**Why?**
Because the action space in our pipeline is geometric (PolygonMask points) and the state space is the original mask baseline. Standard RL libraries like SB3 are heavily optimized for continuous control (Mujoco) or discrete action spaces (Atari) with standard Gym wrappers. Passing variable-length geometric arrays into SB3's generic MLP feature extractors requires extensive custom wrapper engineering that often fights the framework. By writing a custom PyTorch loop, we have direct control over the encoder that projects the polygon coordinates into the low-dimensional latent representation, and direct access to backpropagate specifically through the LoRA adapters on the SAM2 decoder backbone.

## Blue/Green Deployment

This worker implements an automated Blue/Green deployment strategy. Once a batch of 64 tuples has been successfully trained:
1. The new `.safetensors` LoRA weights are packaged.
2. The weights are hot-loaded into the idle "Green" container.
3. Nginx/Traefik routing is flipped to point to the new container.
4. The worker updates its internal `current_serving_version` tracker so that it will ONLY process future replay tuples that were generated by this new checkpoint.
